# CreateLog 制作過程メモ

## 1. 制作概要

CreateLogは、デザイン学習のアウトプットを投稿・記録し、ポートフォリオのように蓄積できる学習支援サービスです。

学習課題を選び、制作物を投稿し、制作意図や使用ツールを記録することで、単なる作品投稿ではなく「学習ログ」として残せることを目指しました。

公開URL：  
https://create-log.vercel.app/

## 2. 制作背景

デザイン学習では、バナー・ロゴ・LP・UIなどを制作しても、作品単体で終わってしまい、制作意図や振り返りが残りにくいと感じていました。

また、初学者や学習中の制作者にとっては、何を作ればよいか分からない、作ったものをどう整理すればよいか分からない、ポートフォリオに載せるまでの導線が作りにくいという課題があります。

CreateLogでは、課題選択から投稿、公開プロフィールへの蓄積までを一連の流れとして設計し、学習の継続と成果の可視化を支援するサービスを目指しました。

---

## 3. 解決したい課題

### 学習成果が散らばりやすい

制作物を作っても、ファイルやSNS投稿だけに残り、制作意図・改善点・使用ツールがまとまって残らないことがあります。

### 何を作るか迷いやすい

初学者は、自由制作よりも「課題」があった方が手を動かしやすい場合があります。

### ポートフォリオ化しにくい

作品はあっても、それを整理して見せる場所がないと、学習の積み重ねが伝わりにくくなります。

### 公開・非公開の管理が必要

学習途中のものや未完成のものは、公開せずに保存したいケースがあります。

---

## 4. ターゲットユーザー

主な対象は、デザイン学習中のユーザーです。

- Webデザインを学び始めた人
- バナー、ロゴ、LP、UIなどの練習をしたい人
- 制作物を整理してポートフォリオ化したい人
- 制作意図や使用ツールを記録しながら振り返りたい人
- 公開できる作品と非公開の学習ログを分けて管理したい人

---

## 5. サービスコンセプト

### 作って終わりにしない、投稿で伸ばすデザイン学習。

CreateLogでは、制作物をただ投稿するだけではなく、制作意図・使用ツール・課題との紐づけを記録します。

これにより、学習の過程を可視化し、公開プロフィールとして蓄積できるサービスを目指しました。

## 8. UI設計で意識したこと

### 白ベースの柔らかいUI

学習サービスとして使いやすくするため、背景は薄いグレー、カードは白を基調にしました。

画像、カテゴリ、使用ツール、投稿者名、詳細導線をカード内に整理し、一覧から内容を把握しやすい構成にしました。

## 10. 権限設計

Supabaseの Row Level Security を使用し、以下の権限設計を行いました。

- 公開投稿は誰でも閲覧可能
- 非公開・下書き投稿は本人のみ閲覧可能
- 投稿作成はログインユーザーのみ可能
- 投稿編集・削除は投稿者本人のみ可能
- プロフィールは誰でも閲覧可能
- プロフィール編集は本人のみ可能
- 画像アップロードはログインユーザーのみ可能

フロントエンド側の表示制御だけでなく、Supabase側でも権限管理を行うことで、実サービスに近い安全性を意識しました。

## 12. 実装で工夫した点

### 課題から投稿作成へつながる導線

課題詳細ページから `themeId` を持って投稿作成ページへ遷移する設計にしました。  
これにより、投稿が単独で存在するのではなく、学習課題と紐づいたアウトプットとして記録できます。

### 投稿ステータスの管理

投稿には `public`、`private`、`draft` の3種類のステータスを持たせました。

公開投稿は投稿一覧や公開プロフィールに表示し、非公開・下書きは本人のマイページにのみ表示されるようにしました。

### 画像アップロード

Supabase Storageを使用し、投稿画像をアップロードできるようにしました。  
アップロード後の画像URLを `posts.image_url` に保存し、投稿一覧・投稿詳細・公開プロフィールで表示しています。

### 本番環境での動的表示対応

Vercel本番環境では静的生成されたページに新規投稿が即時反映されない問題がありました。  
そのため、投稿一覧など最新データが必要なページに `force-dynamic` を設定し、Supabaseから最新データを取得できるようにしました。

### 404ページの作成

Next.js標準の404ではなく、CreateLog用のカスタム404ページを作成しました。  
トップ、課題一覧、投稿一覧へ戻れる導線を設けています。

## 13. 実装中に発生した課題と対応

### SupabaseのRLS権限エラー

初期実装時に、`profiles` や `posts` への挿入・取得で権限エラーが発生しました。

対応として、テーブルごとに `grant` とRLSポリシーを整理し、本人のみ作成・編集・削除できるルールを設定しました。

### useSearchParams のビルドエラー

`/posts/new` で `useSearchParams()` を使用していたため、Next.jsの本番ビルド時にSuspense境界が必要というエラーが発生しました。

対応として、`useSearchParams()` を使用するコンポーネントを `Suspense` で囲み、本番ビルドが通るように修正しました。

### Vercel本番環境で投稿一覧が更新されない問題

投稿一覧ページが静的生成されていたため、新規投稿が即時反映されませんでした。

対応として、`export const dynamic = "force-dynamic";` を追加し、アクセスごとに最新データを取得するようにしました。

## 16. ポートフォリオ掲載時に伝えたいポイント

この制作では、単なる静的なWebサイトではなく、認証・DB・画像アップロード・CRUD・権限管理・本番公開まで一通り実装しました。

特に、以下をアピールポイントにできます。

- Figmaでのサービス設計から実装まで行ったこと
- Supabaseを使って認証・DB・Storageを構築したこと
- RLSを使って本人のみ編集・削除できる設計にしたこと
- Vercelで本番公開し、実際に操作できる状態にしたこと
- 投稿ステータスを設け、公開・非公開・下書きを分けたこと
- 学習ログが公開プロフィールとして蓄積される設計にしたこと

## 17. 制作を通して学んだこと

Next.jsとSupabaseを組み合わせることで、認証・DB・画像アップロードを持つWebアプリを比較的少ない構成で実装できることを学びました。

また、ローカル環境では動作していても、本番環境では静的生成や環境変数、認証URL設定などによって挙動が変わることを経験しました。

この制作を通して、UIだけでなく、データ設計・権限設計・デプロイ後の動作確認まで含めて考える重要性を理解しました。
